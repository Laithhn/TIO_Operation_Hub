# Client logos (A71, 28 Oct 2026)

Every client can have one optional logo. It is shown with the client wherever the hub can show a picture, and it falls back to the
client's initials on a coloured tile when there is no logo or the file cannot be loaded (never a broken image).

## Behaviour

| Area | What happens |
|---|---|
| Add / edit client | *Client logo (optional)*: **Upload logo… / Replace logo…**, **Remove logo**, **Undo logo change**. The chosen file is previewed at once; nothing is sent until **Save client**. The client's own fields are saved first, then the logo (a new client needs its id). Editing other fields never touches the logo. If the logo fails after the client was saved, the message says so and the form stays open (a new client opens in edit mode). |
| Accepted files | PNG, JPG/JPEG, WebP. Maximum 2 MB by default (`ClientLogos__MaxFileKB`), at most 5000 px wide and high (`ClientLogos__MaxPixels`). |
| SVG | **Refused.** An SVG can carry scripts; the hub has no SVG sanitizer and adding one would mean a new package. The message asks for PNG or WebP. (SVG was already blocked for attachments, A46/A48.) |
| Validation | Browser: extension and size, for a quick message. Server: the **content** decides — PNG/JPEG/WebP signatures and header (size in pixels), extension must match the content (a JPEG named `.png` is refused), empty and oversized files refused. The browser's content type is ignored. |
| Storage | Like attachments (A46): on disk under the attachment storage root, in `logos/{random id}.{png|jpg|webp}` — never the user's file name, never in the database. The client row keeps `LogoPath` (relative path), `LogoContentType` (the checked type) and `LogoVersion` (random, renewed on every upload). Paths are generated by the server and checked to stay inside the root (`AttachmentStore.Full`). Moving the storage folder under Settings (A48) moves the logos too. |
| Replace / remove | The old file is deleted after the database change is committed; a failed save deletes the new file (no orphans). Deleting a client (alone or with everything) deletes its logo file, including sub-clients removed with it. |
| Serving | `GET /api/v1/clients/{id}/logo?v={version}` — signed-in users who can see the client (scope filter); `Content-Type` is the checked type, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, `Content-Disposition: inline`. With the current version: `Cache-Control: private, max-age=31536000, immutable`; otherwise `no-cache`. A replaced logo has a new address, so caches never show the old one. |
| URLs | Root-relative `/api/v1/...`, like every other API call of the web client, so they work on the dev server (Vite proxy) and in production (IIS). They are not under `/Reports` (GUI-01). |
| Permissions | Changing or removing the logo needs the same right as editing the client (Client structure → Maintain, within the client's scope). Viewing follows client visibility. Changes are audited ("Client logo added / replaced / removed"); the path and type are not shown in the history, the version change is. |

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/v1/clients/logo-rules` | `{ maxFileKB, maxPixels, extensions }` for the form. |
| GET | `/api/v1/clients/logos` | Every visible client that has a logo: `[{ id, code, logoUrl }]`. One request serves every screen. |
| GET | `/api/v1/clients/{id}/logo?v=` | The image. 404 without a logo. |
| PUT | `/api/v1/clients/{id}/logo` | Multipart, one field `file`. Adds or replaces. Returns `{ logoUrl, width, height, contentType }`. 422 with `errors.file` for invalid files, 403 without the right. |
| DELETE | `/api/v1/clients/{id}/logo` | Removes (204; also when there is none). |
| changed | `GET /clients`, `GET /clients/{id}` | New `logoUrl` (null without a logo) on list rows, the client, its parent and its sub-clients; computed in the same query. |
| changed | `POST /reporting/reports/cases/preview` | Rows also carry `clientId`. |

## Where logos are shown

The React component `ui/ClientLogo.tsx` (`ClientLogo`, `ClientDisplay`, `useClientLogos`) is used everywhere; sizes `xs` 18 px, `sm` 26 px (tables), `md` 48 px (cards), `lg` 96 px (details). Fixed square box, `object-fit: contain`, initials until the image has loaded.

- Clients: list (alias column), client page (identity card, 96 px), parent and sub-clients, client form (preview), region page, projects list, project page.
- Dashboard: *Needs immediate attention*, environment-health and escalation client tables, overdue payments by client, client map side list and map popups.
- Cases list, commitments list and page, escalations list and page, contracts register (project column) and contract page, environments list, servers/assets lists, firewall rules, notifications (client column), products (installations, projects, deployments), data quality, organization structure (diagram and tables).
- Global search palette (client hits).
- Reporting Center → Cases report builder: preview client columns and the client filter list.
- Exports (Cases report builder): **PDF** — logo in the page header of a one-client report and beside the client in the detailed table; **Excel** — logo on the Summary (or Metadata) sheet of a one-client report.

## Not covered (deliberately or technically)

- **Native drop-downs** (`<select>` client pickers and filters): an `<option>` cannot hold an image. They keep native keyboard and screen-reader behaviour and show the alias and name only. The builder's own client filter list shows logos.
- **CSV exports** and the **13 Report Library reports (A62)**: CSV has no pictures; the library reports' rows are generic and carry no client id. Their Excel files are unchanged.
- **WebP in PDF and Excel**: the in-house PDF writer and Excel do not take WebP; such a client shows without a logo there (initials are not drawn in files). PNG (not interlaced) and JPEG are embedded.
- Excel data sheets have no per-row pictures, so sorting and filtering stay exact; multi-client Excel files carry no logos.
- Chart legends and text-only places (breadcrumbs, page-toolbar title, history/audit text, e-mail-like notifications) show no logo.
- Browser **print** prints whatever the screen shows (logos included once loaded).

## Upgrade

Migration `ClientLogo` adds three nullable columns to `clients.Client` (`LogoPath nvarchar(200)`, `LogoContentType nvarchar(50)`, `LogoVersion nvarchar(32)`); it is part of the regenerated `database/01-schema.sql`. No data changes; rollback of the application files is safe (older versions ignore the columns). Back up the attachment folder together with the database as before — it now also holds `logos/`.
