# REST API (v1)

- Base path: `/api/v1`. Full OpenAPI 3 document: served at `/openapi/v1.json` (signed-in users) and saved in [`openapi-v1.json`](openapi-v1.json) (243 operations, refreshed for 2.23.0).
- Health (anonymous): `/api/health/live`, `/api/health/ready`.

## Conventions

| Topic | Rule |
|---|---|
| Sign-in | `Auth:Mode` **Forms** (default; HttpOnly SameSite=Strict session cookie `TioHub.Session`) or **Windows** (Negotiate). Development/Testing only: fixed or header/cookie-selected fictional users. Forms endpoints: `GET /auth/config` (anonymous; issues the XSRF token), `POST /auth/login`, `POST /auth/logout`, `POST /auth/setup` (one-time first administrator), `POST /auth/password` (change own), `POST /admin/users/{id}/password` (administrator issues a temporary password), `GET /admin/users/sign-in-status`. Failures return one generic 401 message; a temporary password allows only `/me` and `/auth/password` (403 *Password change required*) until replaced. |
| Authorization | Checked on the server for every request: active account → business role → client/project/internal-team scope → action → field restrictions (Technical detail) → separate Export/Audit grants. Out-of-scope records return **404**, never their existence. |
| Antiforgery | Every non-GET call needs header `X-XSRF-TOKEN` with the value of the `XSRF-TOKEN` cookie issued by `GET /me`. |
| Concurrency | `GET` on a record returns an `ETag`. Updates and state transitions send `If-Match`. Stale version → **412** (nothing saved); missing → **428**. |
| Errors | RFC 7807 Problem Details: `title`, `detail`, `traceId`, and `errors` keyed by field (422). Duplicates → **409** with a neutral message when the existing record is outside the caller's scope. |
| Lists | `page`, `pageSize` (1–200, default 15), `sort` (`name` or `-name`); response `{ items, page, pageSize, totalCount }`. |
| Time | Instants are ISO-8601 UTC. Deadlines are entered as local wall-clock time + IANA zone (`dueLocal`, `timeZone`); ambiguous DST times need an explicit offset. |
| Evaluation time | `/dashboard`, `/dashboard/actions`, `/cases`, `/commitments` accept `asOf` so counts and drilldowns can be reconciled at a fixed time. |
| No integrations | There is no Jira, vault, monitoring or messaging call anywhere in the API. |

## Resource groups

| Group | Main operations |
|---|---|
| Session | `GET /me` (incl. `app.map` tile template when configured), `PUT /me/preferences`, `GET /reference`, `GET /users/assignable?clientId|teamId` |
| Clients | CRUD (`parentClientId` makes a sub-client; `team: [{userId, role}]` the project team; list filters `parentId`, `level=main|sub`, default sort `tree`), `/duplicates`, `/archive`, `/active-work`, `/overview` (Client 360), regions, contacts, responsibility boundaries; `/regions/{id}`, `/projects` (list with contract counts and renewal attention; `GET /projects/{id}` includes its contracts with renewal state and SLA targets; archive refused while a contract is Active) |
| Environments | CRUD, `/archive`, `/conditions` (manual condition reports), `/overview` (Environment 360) |
| Catalogue | `/products` (+ modules, features, microservices with `/products/microservices/{id}` detail, `/versions` and `/products/microservice-versions/{id}` (release notes), developers in the product body, versions), `/installations` (+ `/version` explicit confirmation, `GET /deployment`, `PUT /deployment/{assetId}` — microservices per server), `/version-matrix` |
| Configuration | `GET/POST /admin/lookups` (lists incl. `EnvironmentType`, `AssetType`, `ContractType`, `CaseType`; `code` optional, `category` required for type lists), `PUT /admin/lookups/{id}`, `GET /admin/lookups/{list}/usage`, `POST /admin/lookups/{list}/order`; records take and return the configured type code in `type` |
| Administration | `GET/POST /admin/roles`, `PUT/DELETE /admin/roles/{id}` (roles with `rights`), users take `roleId`; `/me` returns `roles` (names) and `rights` |
| Inventory | `POST /environments/{id}/clone-to-many` (`targets: [{environmentId, find, replace}]` — any environments of the client, the source included for a renamed duplicate — plus `assetIds`, `installationIds`, `lifecycle`, `includeVolumes`, `includeDeployment`, `copyVersions`, `versionEvidence`; all or nothing), `POST /environments/{id}/clone-environment` (new environment in `regionId` named `name`, then all or the listed `assetIds`/`installationIds` with the clone options), `POST /environments/{id}/clone` (copy servers/installations to another environment of the client: `targetEnvironmentId, assetIds, installationIds, find, replace, lifecycle, includeVolumes, includeDeployment, copyVersions, versionEvidence`), `/assets` (+ volumes; create/edit accept `microservices: [{installationId, hosted: [{microserviceId, versionId}]}]` (the older `microserviceIds` form is still accepted and keeps recorded versions); `PUT /assets/{id}/microservices` changes only the hosted microservices and versions), `/environments/{id}/microservice-options?assetId=` (with versions and the deployed `versionId`), `/shared-storage`, `/components`, `/infrastructure/summary` |
| Notes (own notes only) | `GET /notes/tree` (notebooks, sections, page counts, bin and pinned counts), `POST/PUT/DELETE /notes/notebooks[/{id}]`, `POST /notes/notebooks/reorder`, `POST/PUT/DELETE /notes/sections[/{id}]` (`notebookId` moves a section), `POST /notes/sections/reorder`, `GET /notes/pages?sectionId&q&clientId&projectId&link(personal·client·project·linked)&pinned&deleted`, `GET /notes/pages/{id}`, `POST /notes/pages` (`sectionId`, `title`, `contentHtml`, `level`, `clientId`, `projectId`, `afterPageId`), `PUT /notes/pages/{id}` (If-Match; title, content, level, pin, `sectionId` to move; answers the new version), `PUT /notes/pages/{id}/link`, `POST /notes/pages/reorder`, `DELETE /notes/pages/{id}` (to the recycle bin), `POST /notes/pages/{id}/restore`, `DELETE /notes/pages/{id}/permanent`, `POST /notes/recycle-bin/empty`, `POST /notes/pages/{id}/files` (multipart `file`), `GET /notes/files/{id}`. Other users' notes answer 404. |
| Attachments | `GET /attachments?recordType&recordId` (Client, Region, Project, Contract, Environment, Asset, Installation, Component, Case, Commitment, Escalation, Product, Team), `POST /attachments` (multipart: `recordType`, `recordId`, optional `description`, one or more `files`), `GET /attachments/{id}/download`, `PUT /attachments/{id}` (`description`), `DELETE /attachments/{id}`, `GET /attachments/limits` (size, count, types; the storage folder for administrators). |
| Delete with dependencies (Delete records right) | `GET /dependents/{kind}/{id}` — `kind` is clients, regions, environments, projects, contracts, assets, installations, components, cases, commitments, escalations or teams; returns `label`, `total`, `delete` groups (`label`, `count`, `main`, `items` with `link` and `deletePath`) and `unlink` groups. `DELETE /dependents/{kind}/{id}` deletes the record and everything listed, unlinks the rest, in one transaction. |
| Firewall rules (Technical detail) | `GET /firewall-rules?clientId&environmentId&assetId&protocol&q&sort&page&pageSize` (source/destination server with environment, `ports`, `protocol` TCP·UDP·TCPandUDP·ICMP·Any, `direction` OneWay·Bidirectional, `purpose`, `notes`), `POST`, `PUT /{id}` (If-Match), `DELETE /{id}`. The network endpoint and dependency routes were removed in 2.14.0. |
| Deletion (Delete records right) | `DELETE` on `/clients/{id}`, `/regions/{id}`, `/projects/{id}`, `/contracts/{id}`, `/contacts/{id}`, `/boundaries/{id}`, `/environments/{id}`, `/assets/{id}`, `/installations/{id}`, `/components/{id}`, `/volumes/{id}`, `/cases/{id}`, `/commitments/{id}`, `/teams/{id}`, `/admin/lookups/{id}`, `/products/{id}` (If-Match optional): owned children go with the record; 409 with the using table when something else still uses it. |
| Notifications | `GET /notifications?unread&category=payments&page&pageSize` (`items`, paging, `unreadCount`, `unreadPayments`), `GET /notifications/unread-count`, `POST /notifications/{id}/read`, `POST /notifications/read-all`, `DELETE /notifications/{id}` — always the signed-in user's own notices. |
| Cases | CRUD, `/triage`, `/assign`, `/start`, `/progress`, `/waiting`, `/waiting/clear`, `/request-validation`, `/resume`, `/close`, `/cancel`, `/reopen`, `/due`, `/jira`, `/jira/{refId}/remove`, `/impact`; `/jira/reuse` |
| Commitments | CRUD, `/revise`, `/complete`, `/cancel`, `/reopen` |
| Escalations | `GET /escalations?clientId&projectId&contractId&caseId&status(active·all·Open·Acknowledged·InProgress·Resolved·Closed·Withdrawn)&channel&priority&level&ownerId&overdue&q&country&productId&sort&page&pageSize`, `GET/PUT /escalations/{id}` (If-Match; `channel` from the `EscalationChannel` list, `counterpart` contact details, `responseDueAt`, `resolutionDueAt`), `POST /escalations`, `POST /escalations/{id}/communications` (`channel`, `outgoing`, `at`, `note`), `POST /escalations/{id}/status` (`status`, `note`, `resolutionSummary`), `POST /escalations/{id}/raise-level` (`note`), `DELETE /escalations/{id}` (Delete right). |
| Contracts | `/contracts` list (`renewal=attention|expired|due|unknownEnd|current`, `status`, `type`, `clientId`, `projectId`, `country`, `productId`, `q`), `GET/PUT /contracts/{id}` (`projectId` required; client and covered products come from the project; SLA targets and covered environments in the body; `support24x7`, `supportDays` [Sunday…Saturday], `supportFrom`/`supportTo` HH:mm, `supportTimeZone` (IANA), `supportHours` (notes), `currency` (ISO 4217), `milestones` [phase, description, completionPercent, date], `fees` [description, unit, quantity, unitPrice], `payments` [condition, percentage, amount, dueDate, status Pending·Invoiced·Paid·Waived, paidOn] — rows with `id` are kept, others added, missing ones removed; GET adds `supportSummary`, `feesTotal`, per-row totals and `overdue`), `POST /contracts`, `/archive`; `/export/contracts`; action-list category `ContractRenewal`; notifications `PaymentDue` / `PaymentOverdue` (setting `Contracts.PaymentReminderDays`); `GET /payments?state=attention(default)·overdue·due·upcoming·open·paid·waived·all&clientId&ownerId&mine&productId&country&q&sort(due·amount·contract·client·status·condition)&page&pageSize` (rows with contract, client, owner, `state`, `daysToDue`, plus `summary` of overdue / due / upcoming counts and amounts per currency); action-list category `PaymentDue`; `/dashboard/insights` → `payments` (summary, `byMonth`, `amountsByMonth`, `next`); `/dashboard/insights` → `contracts.renewal` |
| Teams | `/teams` (+ `/{id}/members` POST, `PUT`/`DELETE /{id}/members/{memberId}` — `teamRole` from the TeamMemberRole list, `productFamiliarity` comma-separated product codes; `/assignments`), `/reassignment-queue`, `/handovers` (+ `/candidates`, `/acknowledge`, `/exception`, `/cancel`) |
| Quality | `/review-policies`, `/data-quality` (+ `/summary`, `/scan`). `/reviews` and `/documents` were removed in 2.23.0 (A52). |
| Reporting | `/dashboard`, `/dashboard/actions`, `/dashboard/insights` (chart data, clients by country with a per-client `countries.clients` list, and `contractDetail`: by type, status, 12-month expiries, support model, on-site by client, SLA targets per priority), `/search`, `/export/{cases|commitments|actions|environments|versions|assets|data-quality}` |
| Administration | `/admin/users` (+ deactivate/reactivate), `/admin/scope-targets`, `/admin/group-mappings`, `/admin/lookups`, `/admin/settings`, `GET/PUT /admin/attachment-storage` (`path` or null for the configured folder, `maxFileMB` 1–250, `maxFilesPerUpload` 1–50, `extensions`, `moveFiles`; answers `location`, `moved`, `left`), `/admin/jira-instances`, `/admin/audit`, `/admin/exports`, `/admin/archived` (+ restore), `/admin/corrections/clients/{id}/code` |
