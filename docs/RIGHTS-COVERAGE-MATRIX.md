# Rights coverage matrix

Generated by `dotnet run --project build/RightsManifest` from `Security/RightsCatalog.cs` and `Security/EndpointRights.cs`. Do not edit. `EndpointRightsCoverageTests` fails if an API route has no entry, and `Rights_matrix_is_current` fails if this file is stale.

Screens, menus, tabs and controls are in [RIGHTS-UI-COVERAGE.md](RIGHTS-UI-COVERAGE.md).

**244 rights. 365 API operations:** 7 Authenticated, 14 Dynamic, 102 Handler, 4 Public, 238 Rights.

How to read an operation's decision:

- **Public:** needs no sign-in, for the reason shown.
- **Authenticated:** any signed-in account with access. It returns only the caller's own data or data filtered by right, for the reason shown.
- **Rights:** the listed rights are checked before the handler runs.
- **Handler:** the rights depend on the record (data scope, limited exceptions, workflow), so the handler checks them.
- **Dynamic:** the requirement depends on the record type or a query value, and the filter works it out on each request.

Each right's prerequisites apply too. All record operations also enforce data scope: client, project or team. A record outside scope answers 404.
