# Test blockers and limitations

**Audit date:** 10 November 2026 (Asia/Dubai). **Target:** `https://nb01994.vitronic.de/`. The executed assessment used an existing **TIO Manager** browser session and safe read interactions. It is a point-in-time, evidence-based audit of the tested scope; it is not complete lifecycle, authorization, accessibility, performance or enterprise-release certification.

Confirmed defects, observed operational data risks, source-supported hypotheses and potential capability gaps must remain separate. A displayed button, an accessible route, source code or an existing automated test is not evidence that its workflow passed. A blocked or unexecuted scenario is not a product failure or a pass.

## Data and business-rule limitations

- Dashboard and report figures were inspected and selected cross-view checks were performed. Every KPI denominator, SLA support interval, pause, timezone boundary, backlog reconstruction, penalty, currency treatment and historical revision was not independently recalculated against authoritative data. Unknown/unmeasurable must not be interpreted as zero or compliance.
- Contract CT-1001's reported holiday exclusion and the disclosed absence of a holiday model require a contract-specific reconciliation. No specific incorrectly calculated deadline/breach/penalty was proven. [Calendar analysis](traces/dashboard-window-and-holiday-analysis.md).
- The catalog's missing configured-status choices are a confirmed finding, but the Pending validation preview returning zero does **not** prove that it should equal the configured Resolved cohort. Configured status and internal stage are distinct. [Status analysis](traces/catalog-status-source-analysis.md).
- Existing Completed exports with hidden metadata are consistent with deliberate access-fingerprint masking. The actual saved fingerprint, file presence and deployment/account-change history were not inspected; missing metadata is not proof of generation or retention failure. [Export analysis](traces/exports-source-review.md).
- The displayed negative audit `Tio user id` is confirmed, while the stored original audit JSON and actual mapping row were not queried. Do not infer a negative persisted business foreign key, failed user creation or security breach from the rounded displayed value alone. [Audit analysis](traces/audit-mapping-source-analysis.md).
- A dedicated change/CAB/release process, live availability monitoring, capacity/shift planning or go-live gate not demonstrated in this hub is a potential capability/scope gap, not automatically an existing software defect. An authoritative external process may exist. [Business-process assessment](06-business-process-gaps.md).

## Accessibility, browser and technical instrumentation limits

The audit did not run axe or another automated accessibility scanner, a complete WCAG 2.2 AA audit, assistive-technology/screen-reader testing, exhaustive keyboard traversal/focus-order tests, contrast verification for every state, or every error-message/target-size/zoom/reflow scenario. Manual findings and measured selected layout observations must remain separate from automated conformance claims. Four representative viewports do not establish all browser/device combinations, high zoom, orientation changes or touch behavior.

No complete authenticated HAR/network log, resource waterfall, console/JavaScript-exception capture, repeated-request analysis, navigation/resource timing baseline, heap/memory profile, CPU/long-task profile or rendering trace was collected. Absence of a visible error does not establish absence of console/API/resource failures. Controlled offline/timeout/dependency-failure, retry, error-boundary and crash-recovery scenarios were not performed.

No load, stress, concurrency, soak, capacity or tail-latency test occurred. Native one-request HTTP samples and UI-displayed query durations are not browser rendering measurements, p95/p99, throughput, availability or enterprise SLO evidence. Audit tool-to-snapshot intervals include tool/evidence overhead and must not be reported as application loading time. [Performance methodology and remaining scope](08-performance-report.md).

No exploitation, credential guessing, automated vulnerability scan, intrusive input attack, data exfiltration or authentication bypass was performed. Browser storage/session secrets, full TLS protocols/ciphers, server/file ACLs, database grants and production log-redaction effectiveness were not comprehensively verified.

## Prepared automation is not executed coverage

The independent Playwright scaffold exists under [test-automation](test-automation/README.md) and currently defines **298 cases in four files**. These include four statically skipped Notes cases and a skipped export-UX proposal. Other cases require explicit read-only target opt-in, an approved private session and, for status consistency, approved existing record fixtures.

**No application test from this scaffold ran against the target.** Local validation passed: all JavaScript syntax checks, **8 pure local policy tests**, and Playwright test discovery. Discovery's skipped entries are not live attempted scenarios or passes. No .NET suite, frontend build or existing database-backed development Playwright suite was launched by this automation subtask. [Exact validation](traces/automation-validation.md).

The harness blocks mutations, external requests, action-like GET paths and Notes GET side effects. It also blocks legitimate POST-based read previews and some export-history paths conservatively; such harness restrictions are blocked coverage, not application defects. A passing future route test would establish only its explicit assertions, not complete business correctness or authorization.

## Completion needed before broader operational assurance

Approve an isolated validation environment and representative account/role/data matrix; identify the deployed package/commit; rerun repaired findings against that exact build; execute complete business lifecycles and rights-denial tests; reconcile contractual KPI/SLA evidence; verify output files and approved integrations; and collect controlled accessibility, browser-performance and recovery evidence. Retain each blocked area in the release decision until its supporting test evidence exists. No speculative numeric score should replace a **Not Rated** dimension where the evidence is insufficient.
